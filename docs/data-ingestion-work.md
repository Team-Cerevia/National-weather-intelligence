# DATA INGESTION ENGINE

## Teammate 1 — Implementation Specification

**Branch:** `feat/data-ingestion`

**Owner:** Data Acquisition, Source Adapters & Normalization

---

# 1. Mission

You own the **complete data acquisition layer** of the National Weather Intelligence Platform.

Your job is to answer:

> **"How does weather-related information from the outside world enter our platform?"**

The platform must be capable of ingesting information from multiple heterogeneous sources:

1. Official weather APIs
2. Weather-data APIs
3. Social-media posts
4. News/web sources
5. Public datasets
6. Citizen reports
7. Synthetic/replay data for testing

All sources must ultimately be converted into one canonical representation:

```text
WeatherReport
```

The downstream system must NOT need to know where the report originally came from.

---

## YOU OWN

* Source adapters

* Public dataset loaders
* Citizen-report ingestion
* Synthetic data generation/loading
* Source-specific parsing
* Data normalization
* Basic metadata validation
* Source metadata preservation
* Basic deterministic duplicate detection
* Source-level tests

* NLP classification

* misinformation detection
* semantic embeddings
* semantic duplicate detection
* incident clustering
* evidence scoring
* verification scoring
* dashboard
* Redis consumer logic
* retry/DLQ logic

Those belong to the downstream intelligence/streaming layers.

# 5. Canonical Data Contract

This is the most important part of your work.

Create:

```text
ingestion/models/weather_report.py
```

Use a Pydantic model.

Minimum schema:

```python
WeatherReport
```

with:

```text
report_id
source
source_type
source_id
timestamp
text
latitude
longitude
city
state
country
url
media_urls
hashtags
raw_payload
```

## Field definitions

### report_id

Internal UUID generated by our platform.

It must be unique even if two different sources refer to the same real-world event.

---

### source

Examples:

```text
imd
open_meteo
x
news
citizen
dataset
synthetic
```

---

### source_type

Examples:

```text
official
weather_api
social_media
news
citizen
public_dataset
synthetic
```

---

### source_id

Original source identifier when available.

Examples:

```text
X post ID
news article ID
IMD bulletin ID
dataset row ID
citizen report ID
```

---

### timestamp

Time associated with the observation/report.

Normalize internally to UTC.

---

### text

Human-readable weather-related text.

For social media/news/citizen reports:

```text
Use the original text.
```

For structured weather APIs:

Generate a deterministic textual description from available fields if necessary.

Example:

```text
"Rainfall of 18.4 mm observed near Delhi with
wind speed of 22 km/h."
```

---

### latitude / longitude

Optional.

Do NOT invent coordinates.

---

### city / state

Optional normalized location.

---

### country

Default to:

```text
India
```

when the source is known to concern an Indian location.

---

### url

Original source URL when available.

---

### media_urls

List of image/video URLs where available.

Do not download large media files for the MVP.

Preserve URLs/metadata.

---

### hashtags

List of hashtags associated with the source.

Especially important for social media.

---

### raw_payload

Preserve the original source payload whenever practical.

This is important for:

* debugging
* traceability
* future reprocessing
* demonstrating provenance
